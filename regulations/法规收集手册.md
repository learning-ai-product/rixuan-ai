## 第 2 步：照着示例填

表格有 9 列，含义如下：

| 列名 | 填什么 | 例子 |
|---|---|---|
| `id` | 自己编号：市场-法律-数字 | `JP-PSE-001` |
| `market` | 市场代码 | `JP` / `DE` / `FR` / `US` / `UK` / `ALL` |
| `category` | 品类 | `electronics` / `beauty` / `baby` / `food` / `home` / `ALL` |
| `lang` | 原文语言 | `ja` 日文 / `zh` 中文 / `en` 英文 |
| `title` | 法规中文名 | `电气用品安全法（PSE）` |
| `text` | **最重要**：50–150 字的实操结论 | 见下 |
| `source` | 官网网址 | `https://www.meti.go.jp/...` |
| `verified` | 是否已核对官网原文 | `是` / `否` |
| `note` | 备注（可留空）| `2026-10-19 从官网摘录` |

### `text` 这一列怎么写（最关键）

不要抄整部法律。**只写「什么算违规」+「卖家要做什么」**，用你自己的话概括成 50–150 字。

✅ 好的写法：

> 日本对电气用品实行 PSE 制度。特定电气用品（如充电器）须加贴菱形 PSE 标志并由第三方认证机构检查；一般电气用品加贴圆形 PSE 标志。未取得标志不得在日本销售。

❌ 不好的写法：
- 复制整页法条原文（太长，检索反而查不准）
- 只写"PSE 认证"（太短，没有可用信息）

### `verified` 这一列

- 从官网**亲自核对过**原文 → 填 `是`
- 我预填的 9 条示例 → 都是 `否`，**你核对完记得改成 `是`**

> 这一列很重要。面试时说"30 条全部 verified=true，逐条从官网摘录"，含金量完全不一样。

## 第 5 步：验证能不能查到


## 常见问题

**Q：CSV 打开是乱码？**
A：用 Numbers 打开。Excel 有时不认 UTF-8，Numbers 没问题。

**Q：我不想装 Numbers 怎么办？**
A：Mac 自带的"文本编辑"也能打开 CSV，只是没有表格格子。右键文件 → 打开方式 → 文本编辑。注意列之间用英文逗号分隔。

**Q：`id` 怎么编？**
A：`市场-法律缩写-数字`，比如 `JP-PSE-001`、`JP-PSE-002`、`US-CPSC-001`。数字顺延，不要重复。

**Q：`category` 用哪个？**
A：和 `app.py` 里的风险表保持一致，只有 5 个：`electronics` / `beauty` / `baby` / `food` / `home`。不确定就用 `ALL`。

**Q：填错了怎么办？**
A：改完重新跑第 4 步的命令就行。原文件会自动备份成 `corpus.jsonl.bak`。

**Q：为什么不用向量数据库？**
A：法规条款短、术语密集，关键词检索命中率更高，而且**能说清依据第几条**——合规场景必须可追溯。这是产品判断，面试时讲出来是加分项。
